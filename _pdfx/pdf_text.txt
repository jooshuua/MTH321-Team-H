AbstractThis project develops and validates a reproducible numerical workflow for two financial stochasticdifferential equations (SDEs). Geometric Brownian motion (GBM) is first used as an exact benchmark:Euler–Maruyama (EM), scalar Milstein, and exact lognormal transitions are driven by identical Brownianincrements. This coupling isolates time-discretisation error from sampling noise. With300,000paths,the fitted terminal strong-convergence slopes are0.4899 ± 0.0026for EM and0.9099 ± 0.0167forMilstein, consistent with the theoretical orders1/2and1. The exactly evaluable bias inE[S
T

The experiment also checks theterminal lognormal law and demonstrates that price-space updates are not unconditionally positivitypreserving. We then solve a bounded, non-affine stochastic-volatility model in log price. Coarse pathsare coupled to anN

1 Introduction and motivation
1.1 Problem backgroundAn SDE model is useful only if its numerical error can be separated from Monte Carlo uncertainty. GBM istherefore more than a toy model: its exact pathwise transition, moments, and terminal distribution providean oracle against which an implementation can be tested. Higham’s algorithmic treatment emphasisesprecisely this role of coupled paths when illustrating EM and Milstein [1]; the broader convergence theoryis developed by Kloeden and Platen [2] and Milstein [3].The project asks a second, more practically relevant question: what changes when no exact transitionis available? We answer it with the prescribed two-factor non-affine stochastic-volatility model. Thesame Brownian path is represented on nested grids, so agreement under refinement becomes evidence forconvergence. It is not relabelled as an exact error. This distinction is central to reliable computationalfinance and underlies multilevel coupling methods [4].
1.2 Research questions and contribution
The numerical investigation addresses four questions.
1.Do coupled simulations recover the predicted GBM strong orders1/2(EM) and1(Milstein), andweak order 1 for the mean?
2. At a matched strong-error target, which method uses fewer time-step coefficient evaluations?
3.When can price-space updates lose positivity, and does the simulated terminal law agree with the exactlognormal distribution?
4.For the non-affine model, do nested-grid EM solutions converge, pass Brownian-increment checks,remain finite and positive, and use a sufficiently resolved numerical reference?The main contribution is a single, auditable script that implements every scheme, fixes all seeds,regenerates every figure and printed number, and runs explicit PASS/FAIL checks. The analysis deliberatelyseparates theorem, measurement, and limitation.
1.3 Report mapSection 2 defines both models. Section 3 derives the numerical schemes and convergence estimators.Section 4 documents the implementation and validation design. Section 5 presents GBM and non-affineexperiments. Section 6 identifies what the evidence does not establish, and Section 7 concludes. Thecomplete source and AI/individual-contribution records appear in the appendices.

4.4 Oracle chain and automatic checksTwo independent GBM oracles are used: the pathwise exact transition and the closed-form terminalmoments/distribution. The non-affine reference is checked by an independent finer grid. Ten automaticchecks cover expected-order bands, the exact GBM mean, both increment variances, target correlation,finiteness, positivity, and a plausible non-affine strong slope. All ten pass in the archived output. The checksare deliberately broad enough to avoid passing only one random realisation, yet narrow enough to catch awrong increment scaling, correlation formula, or scheme.

4.5 Declared cost measureThe cost measure is the number of time steps per path, equivalently one drift/diffusion coefficient evaluationper step in the implemented scalar GBM loop. The comparison excludes plotting, random-number setup,file I/O, compilation, and vector-allocation overhead. It also does not pretend that an EM and a Milsteinstep have identical floating-point operation counts: Milstein evaluates an extra correction. The reportedratio is therefore an algorithmic step-count comparison, not a wall-clock speedup claim.

6 Limitations and robustness
1.Numerical reference. The non-affine error is relative to EM with 2048 steps. Equation(33)quantifies,but does not eliminate, reference bias.
2.Weak convergence resolution. Paired common random numbers reduce variance, yet the call-biasintervals still contain zero. The report therefore does not manufacture a weak slope. More paths,multilevel Monte Carlo, or a different payoff would be needed.
3.Regression uncertainty. Slope standard errors diagnose the chosen log–log fit. They are not theoremproofs and do not include every model-selection uncertainty, such as mesh-range choice.
4.Cost definition. Step count is portable but omits the extra arithmetic in Milstein and hardware effects.A wall-clock study should use repeated timings on the same machine and separately count randomdraws and coefficient/derivative evaluations.
5.Model risk. Numerical convergence does not validate GBM or the non-affine model as a descriptionof market data. Calibration, risk-neutral drift, transaction costs, jumps, and empirical fit are outsidethis numerical-analysis project.
6.Extreme paths. The stable logistic evaluation and batched finiteness checks reduce numerical risk,bute
Xcan overflow under much longer horizons or more extreme parameters. Production code shouldretain log values and define an overflow policy.

•Exact GBM coupling recovered the expected strong orders: EM0.4899±0.0026and Milstein0.9099±

•For the non-affine model, nested Brownian coupling produced empirical half-order strong convergenceand passed variance, correlation, finiteness, positivity, and reference-refinement checks. Weak payoffbias remained unresolved at the available Monte Carlo precision.

248 def logistic_vol (y: np.ndarray , p: NonAffineParameters ) -> np.ndarray:

249 """Bounded logistic volatility , evaluated without overflow."""

250 positive = y >= 0

251 q = np.empty_like(y, dtype=float)
17

252 q[positive] = 1.0 / (1.0 + np.exp(-y[positive ]))

253 ey = np.exp(y[~ positive ])

254 q[~ positive] = ey / (1.0 + ey)

255 return p.sigma_min + (p.sigma_max - p.sigma_min) * q
